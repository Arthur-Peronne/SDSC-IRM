## Hypothesis
Fusion of two prior ideas. Parent 1: `ac5057cf` (new CHAMPION, se3-only — dropping se4 from
`761cab78` beat every other SE-placement combination, 0.7167, AND gave this campaign's best-ever R²
0.7432). Parent 2: `2647e285` (near-miss FAILURE on top of `761cab78` — `bottleneck_conv`'s two
`InstanceNorm3d` replaced by `GroupNorm(8,128)`, gave the previous-best R² 0.7419 but only
0.6917 accuracy, a -0.0083 near-tie). Both changes independently pushed reconstruction quality up;
`2647e285`'s conclusion explicitly speculated GroupNorm's extra information might be
reconstruction-relevant rather than classification-relevant on its own, but that test was run on the
`761cab78` architecture (with se4 still present). Testing whether GroupNorm's benefit transfers
differently on top of the leaner, better `ac5057cf` encoder — the two changes touch non-overlapping
locations (SE placement in the encoder vs. `bottleneck_conv`'s normalization), so there's no obvious
reason they should cancel out, and stacking two independently-R²-positive changes is a reasonable next
step now that a real (not just tied) champion exists to build on. No encoder-to-decoder path —
respects the no-skip-connections rule.

## Conclusion
Hypothesis falsified: the two independently-positive changes did not compose. Not only did
classification accuracy fail to improve (0.6583, delta -0.0583, a clear miss, not a near-tie), R²
itself came in below both parent trials' individual results — this isn't "one gain cancels the other
out to neutral," it's a genuine regression on the reconstruction axis too. Mechanistic read: `se3`'s
gate produces a channel-recalibrated 64-channel feature map that already differs from what
`bottleneck_conv` saw in the `2647e285`/`761cab78` lineage (where se4 also ran right before it) —
GroupNorm's grouped normalization assumes a specific channel-covariance structure to exploit, and it's
plausible that removing se4 changes exactly that structure enough that GroupNorm's grouping
(channels 1-16, 17-32, ... arbitrary contiguous blocks of the 128 output channels) no longer aligns
usefully with it. This is a caution against assuming independently-validated changes compose by
default, even when they touch non-overlapping locations — the champion `ac5057cf`'s specific win may
depend on `bottleneck_conv`'s plain InstanceNorm3d in a way that wasn't obvious from testing GroupNorm
on the older `761cab78` lineage alone. Reverting to `ac5057cf` as the base for the next trial; if
GroupNorm is revisited, it should not be assumed compatible with se3-only without being retested
directly, not inferred from the two individual results.
