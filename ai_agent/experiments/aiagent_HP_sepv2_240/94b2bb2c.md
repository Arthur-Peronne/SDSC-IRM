# Trial 94b2bb2c — AE3dAsymResSeparableV2 — FAILURE

<!-- ===== written BEFORE the run (agent) ===== -->

## Hypothesis
Trials 6a8a38d6 (dropout), 5fb49bb5 (weight_decay), and e44c7fa6 (lower lr) all FAILED,
via three different mechanisms, all of which act on the model's weights or the
optimization trajectory. `noise_std` (input-space Gaussian corruption, denoising-AE
style) is mechanistically different: it does not restrain the weights or the
optimizer, it changes what the model is trained to reconstruct FROM — a corrupted
input mapped back to a clean target. This encourages the encoder to learn features
robust to small perturbations rather than exact-pixel fitting, which could reduce
val-time sensitivity to the natural patient-to-patient variability without touching
model capacity or step size (the two things already shown to hurt when altered). I use
`noise_std=0.002`, the magnitude already validated by the project's own Optuna search
(AEoptuna value noted in the YAML comment) for a comparable setting. I predict
`avg_validation_R2_mean` improves above 0.8075.

## Implementation
Single-field change in `configs/autoencoder.yaml`: `noise_std: 0.0 -> 0.002`. All other
hyperparameters unchanged from the baseline (lr=5e-4, weight_decay=0.0,
dropout_rate=0.0, patience=30). No architectural change.

## Training Dynamics
Much more disruptive than any prior trial: `best_epoch=9` (vs 66 in the baseline),
early-stopped at epoch 39 (9+30). `val_loss` is markedly noisier from the start —
spikes to 0.00336 at epoch 12, stays elevated and jittery (0.0019-0.0021) through
epoch 39, never approaching the baseline's ~0.00055 floor. `train_loss` keeps falling
smoothly (0.00107 by epoch 39) but never drives `val_loss` down with it. Final
`train_R2_mean` (0.650) is far below the baseline's (0.859) — this is not merely a
generalization-gap story, training itself is degraded, and validation's high std
(0.2455 vs baseline's 0.067) shows the noise made performance wildly inconsistent
across patients.

## Conclusion
Hypothesis clearly rejected, and this is the worst FAILURE of the campaign so far
(0.807 -> 0.622, delta -0.185 — an order of magnitude larger than the other three).
Mechanistic read: `noise_std=0.002` (borrowed from an Optuna search run under
different conditions — smaller model/architecture and/or different loss weighting)
is far too aggressive a corruption for this model/data combination at
`latent_dim=240`. With `batch_size=1`, every gradient step sees one single noisy
realization with no batch averaging to cancel it out, so the effective training
signal is dominated by noise rather than smoothed by it — the opposite of the
intended denoising-regularization effect. Borrowing a HP value tuned in a different
context without rescaling for this pipeline's own conditions (batch size, input
scale) was the wrong move. Champion remains 185cf97f. Takeaway for future noise_std
trials (if tried again): use a much smaller magnitude than the borrowed Optuna value,
not the same one. Next trial moves to the last untried opened axis (`patience`)
rather than retrying noise_std at a smaller value immediately, to finish a first
single-axis pass around the baseline before revisiting magnitudes.
