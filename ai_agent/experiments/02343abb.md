# Trial 02343abb — AE3dAsymResSeparableV2 — CHAMPION

<!-- ===== written BEFORE the run (agent) ===== -->

## Hypothesis
At dim=60, noise_std showed a sharp, non-monotonic cliff around a narrow sweet
spot: 0.0001 was CHAMPION (input-noise denoising acting as a mild regularizer),
but the ablation (noise_std=0.0, i.e. removing it) cost -0.012 there too — so the
effect wasn't just "any regularization helps," the exact value mattered. At dim=8
the bottleneck itself is already a much stronger implicit regularizer (7.5x fewer
latent dims), so denoising-as-regularization may be redundant here and add nothing
(or even remove useful signal the tiny bottleneck needs). I ablate noise_std to 0.0
to test whether the dim=8 baseline's R²=0.7977 depends on it at all, isolating
this axis before deciding whether to keep tuning it.

## Implementation
`configs/autoencoder.yaml`: `noise_std: 0.0001 -> 0.0`. Everything else identical
to the BASELINE (0d2e0fa2): lr=6e-4, weight_decay=0.0, dropout_rate=0.0,
patience=50, latent_dimensions=8.

## Conclusion
Hypothesis confirmed: removing noise_std improves things at dim=8 (+0.0079),
the opposite sign from dim=60 where the same ablation cost -0.012. This is a
direct, mechanistically coherent divergence between the two capacity regimes: at
dim=60 a small denoising perturbation was a useful regularizer against a larger
model's overfitting; at dim=8 the bottleneck alone already regularizes enough,
and adding input noise on top just injects irrelevant variance the tiny latent
code has to spend capacity absorbing rather than encoding signal. New CHAMPION
(0.8056, delta +0.0079) — though note this delta is still inside the ~0.03-0.04
noise floor, so I'm not overclaiming a large effect, just accepting it as the best
point found so far per the deterministic rule. Next: dropout_rate, now against
this new noise_std=0 baseline — testing whether the "dim=8 needs less
regularization than dim=60" pattern extends to dropout too.
